# Task 06: Real-Time ML Inference REST API & Capstone

## Purpose

This FastAPI service exposes the saved Task-04 customer-churn classifier for single-record inference. It loads the existing fitted scikit-learn Pipeline using joblib; the saved `ColumnTransformer` and Logistic Regression model are reused together. The API does not retrain the model and does not use `customer_id`.

The model artifact was inspected before defining the request contract. It expects the following features, in this order, and predicts the existing binary target labels `0` and `1`:

| Request field | Observed meaning/type | Validation |
|---|---|---|
| `tenure_months` | Numeric tenure, integer in the CSV | Integer, non-negative |
| `support_tickets` | Numeric support-ticket count, integer in the CSV | Integer, non-negative |
| `monthly_spend_inr` | Numeric monthly spend in INR, integer in the CSV | Number, non-negative |
| `last_login_days` | Numeric days-since-login value, integer in the CSV | Integer, non-negative |
| `plan_type` | Categorical plan type | One of `Basic`, `Pro`, `Standard` |

The saved artifact is a fitted `Pipeline` containing a `ColumnTransformer` and `LogisticRegression`. It exposes `predict_proba()`, with model classes `0` and `1`. The request excludes `customer_id` and forbids additional fields. The data card does not define the operational churn horizon, so class outputs should be interpreted only as the artifact's labels, not as a guarantee about a customer's future.

## API

- `GET /health`: returns readiness when the model artifact is available; otherwise responds with HTTP 503.
- `POST /predict`: validates one raw input record, passes it to the fitted pipeline, and returns its predicted class and computed class probabilities.
- `GET /docs`: interactive OpenAPI documentation.

### Example request

This request uses feature values present in the supplied CSV:

```json
{
  "tenure_months": 18,
  "support_tickets": 1,
  "monthly_spend_inr": 1299,
  "last_login_days": 2,
  "plan_type": "Pro"
}
```

### Response schema

Values below are placeholders describing the response shape, not a saved or fabricated inference result. Actual values are generated by the loaded model:

```json
{
  "predicted_class": "<model-predicted integer class>",
  "class_probabilities": {
    "0": "<computed model probability>",
    "1": "<computed model probability>"
  }
}
```

When the fitted model does not provide probabilities, `class_probabilities` is `null`. Request validation failures return HTTP 422; an unavailable or incompatible model returns HTTP 503; inference failures return a generic HTTP 500 response without internal stack details.

## Architecture

```text
Validated JSON
  -> Pydantic request validation
  -> pandas DataFrame with the model's observed input columns
  -> saved scikit-learn Pipeline (preprocessing + classifier)
  -> predicted class and model probability scores
```

The service checks the loaded artifact's feature names and classes. If the file is missing, unreadable, or incompatible, it serves no fake predictions and reports the model as unavailable.

## Install and run locally

Use Python 3.13 to match the environment used for the saved artifact and install the pinned Task-06 dependencies:

```powershell
py -3.13 -m pip install -r Task-06/requirements.txt
```

Run Uvicorn from the repository root:

```powershell
py -3.13 -m uvicorn app:app --app-dir Task-06 --host 127.0.0.1 --port 8000
```

Alternatively, change into `Task-06` and run `py -3.13 -m uvicorn app:app --host 127.0.0.1 --port 8000`. The application locates the saved artifact relative to its own file, so its working directory does not determine model discovery.

Open the interactive docs at <http://127.0.0.1:8000/docs>.

### Example curl request

```powershell
curl.exe -X POST "http://127.0.0.1:8000/predict" `
  -H "Content-Type: application/json" `
  -d '{"tenure_months":18,"support_tickets":1,"monthly_spend_inr":1299,"last_login_days":2,"plan_type":"Pro"}'
```

## Docker

Build from the repository root. The Dockerfile copies only the Task-06 requirements and application plus the existing Task-04 model artifact; it does not copy the repository or dataset:

```powershell
docker build -f Task-06/Dockerfile -t churn-inference:task06 .
```

Run the container:

```powershell
docker run --rm -p 8000:8000 churn-inference:task06
```

Then visit <http://127.0.0.1:8000/docs>.

## Tests

From the repository root:

```powershell
py -3.13 -m pytest -q -p no:cacheprovider Task-06/test_app.py
```

Tests use the real saved artifact for health and valid prediction integration cases. They also check required and invalid fields, unsupported plan values, response shape, missing-model behavior, and sanitized inference errors.

## Limitations and responsible use

The model was trained on only 12 records. Its performance is not a reliable estimate of production behavior and its probabilities are not necessarily well-calibrated. The data has no timestamps or documented prediction window; the meaning of `churned` beyond the supplied labels cannot be determined from the available files. The API validates values and reuses the saved training preprocessing, but this does not establish that all fields are available at any real prediction time.

Use outputs for educational evaluation and possible human-supported review only. Predictions can be wrong and should not automatically trigger retention actions, pricing changes, account restrictions, or other decisions. Real-world use would require permission and privacy review, substantially more representative data, independent validation, fairness and calibration assessment, and ongoing monitoring.
